# Upgrade existing voice-mode branch installations

Protocol 6 requires a matching host, worker and client. Detect an existing installation by its `voice-mode-worker` package script and voice-mode files; inspect the deployed Git revision and service paths privately. A stale worker or browser tab cannot speak the new command, review and caption namespace reliably. Existing configured `VOICE_MODE_LINK_TOKEN` personal links keep their `voice-mode:` identities and `/voice?t=` URLs. Newly minted per-agent links use the module's own hashed-token table. Core users, roles, memberships and sessions remain unchanged.

1. Close call admission at the HTTPS front and drain current rooms/jobs. Stop the old worker and host. Save the exact Git revision, lockfile, private `.env`, worker service definition, front routing, explicit group skill lists, vocabulary and acoustic model paths. Take a consistent backup of the central DB; quiesce containers if backing up session mailboxes too.
2. Build the chosen protocol 6 revision with a frozen dependency install. Remove stale compiled voice worker files before building. The worker now runs `dist/channels/voice-mode-worker.js start`; its default dispatch name is `nanoclaw-voice-mode`. Keep an explicit existing `LIVEKIT_AGENT_NAME` identical on host and worker, or change both together. Follow [worker service installation](../.claude/skills/add-voice-mode/references/2610-07-services.md) and retire only this checkout's old service.
3. Preserve `VOICE_MODE_*` values. Bare `VOICE_*` aliases are not supported by this contribution; rename any operator-defined aliases privately to the corresponding `VOICE_MODE_*` setting. The default language is English; configure `VOICE_MODE_LANGUAGES` explicitly when another language is needed. Preserve custom model, phrase, threshold and vocabulary settings.
4. Add `voice-mode-formatting` to each explicit skill list using `pnpm exec tsx scripts/voice-mode-install.ts guidance-add <group-id>`. Restart the host, worker and affected groups. Reload browser tabs. A separately maintained native client must support protocol 6 before admission reopens; keep its previous compatible build for rollback.
5. Verify protocol/dispatch name on loopback worker health, acoustic model loading without fallback, a saved `/voice?t=` link, one automatic send, one reviewed send/discard, captions, audible reply and reconnect. Reopen the front only when the private test line succeeds. Keep production tokens out of screenshots and reports.

For rollback, close admission and drain again. Stop both processes, restore the recorded source revision, frozen dependencies, private configuration, front and service paths, skill selections and compatible client. Clean stale compiled files and build before restart. Prefer preserving new messages; restoring a DB snapshot discards post-backup changes and can reactivate links retired since that snapshot. Confirm the restored test line works before reopening calls. This contribution does not perform an automatic deployment or native-client upgrade.
