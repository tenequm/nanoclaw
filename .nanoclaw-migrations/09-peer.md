## Verify

Run `pnpm check --base origin/main` and the peer routing, CLI and mailbox tests against the replayed source. On a disposable test stack, confirm a network-admitted hello through Caddy, directory refresh and removal in a running agent, and a reply to the originating session. Use test identities for live messages.

When replaying A2, verify these cases against the assembled hub and daemon:

- Retry a lost signed hello with the same process `instance`. It gets the same epoch after reconnect, hub restart or inactivity lapse. A different instance gets the next epoch after lapse or on takeover. A refused hello (including 426) preserves ownership and the stream. Writes and streams require a live epoch; stale and never-issued epochs get `409 superseded`, with the current epoch only while one is live. The `log` id persists with the event log. Switching logs resets the daemon's cursor and outbox, keeps its delivered-id record and notifies senders with discarded outbox entries.
- Reconnect after an endpoint's original event is behind the cursor. The hub snapshots every open endpoint with a non-ended key, without an SSE id before replay. Ending the last key logs a closed endpoint and removes it from the snapshot. R9 takeover reopens the original endpoint. The daemon binds its relays, processes the replay, then reconciles its directory from the full status list at `synchronized`.
- Register two live keys on one machine with the same `sessionId`. Each has its own hub session with the agent. When a new key resumes an ended key's `sessionId` on that machine, it takes over the hub session and endpoints.
- Interrupt routing to an agent while a message is `queued`. Retry by id and mark it `accepted` after exactly one inbox write. On a routing failure, tell the sender it was `dropped` with `route_failed` or a refusal such as `not_member`. Preserve `failureNotice` on the peer outbox row and in the host's inbound content allowlist. A failed turn woken solely by a marked notice emits no return notice.
- Cross the hop limit twice. The first refusal tells both parties. A stopped native reply gets one outgoing limit event in addition to its HTTP refusal. An agent sender gets one host notice per episode; later refusals are logged. New refused machine sends count against the machine rate. The message's `origin` cannot reset the pair. A session's human-turn report or an owner message to the agent resets the counter and chain together. For a pair of mesh agents, an owner message to either resets the pair. Check that the next delivery carries `hopChain: []`.
- Replay a stored send after the target has ended or the conversation is at the limit. A live-epoch retry returns the stored state or `id_conflict` before membership, target, hop, queue and rate checks. Confirm no additional charge, hop, event or session write.
- Submit a delivery report from another machine or another session. Both return `applied: false`, `state: null`. Advance one machine's heartbeat cursor and verify only its incoming messages advance.
- Apply the agent delivery migration to A1 data. Stored agent successes and their replay events read `accepted`; a held native message released as `delivered` retains that state.
